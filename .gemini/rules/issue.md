# 이슈 작성 규칙

이 문서는 Antigravity Agent가 이 저장소에서 이슈를 작성할 때 참고하는 규칙이다. 템플릿은 [.github/ISSUE_TEMPLATE/이슈-템플릿.md](../../.github/ISSUE_TEMPLATE/이슈-템플릿.md)를 따른다.

## 제목

`<타입>: <작업 요약>` 형식으로 작성한다.

예: `docs: 개발 로드맵 문서 작성`

**타입:**

- `feat`: 새로운 기능
- `fix`: 버그 수정
- `docs`: 문서화
- `style`: 포맷팅
- `refactor`: 코드 리팩토링
- `perf`: 성능 개선
- `test`: 테스트
- `chore`: 빌드/도구
- `ci`: CI 관련 설정 수정에 대한 커밋

```markdown
## 🌌 배경

## 🪐 작업 요약

## 📜 TODO
- [ ]
```

## 전체 원칙: 간결함

이슈는 **길게 쓰지 않는다.** 배경 설명이 장황해지거나 TODO가 지나치게 세분화되면 오히려 파악이 어려워진다. 한 화면 안에서 스크롤 없이 훑어볼 수 있는 분량을 기준으로 삼는다. 자세한 설계 논의나 근거는 이슈에 풀어 쓰지 않고 `docs/PRD.md`, `docs/ROADMAP.md` 등 관련 문서를 링크로 참조한다.

## 🌌 배경

- 이 작업이 왜 필요한지 1~2문장으로만 적는다.
- 관련 PRD/ROADMAP 섹션이 있으면 문장 대신 링크로 대체한다.

## 🪐 작업 요약

- 무엇을 할 것인지 한두 문장으로 요약한다.
- 범위가 여러 갈래면 `-` bullet으로 나열하되, 항목은 3~4개를 넘기지 않는다. 그 이상 나뉘면 이슈를 분리하는 것을 고려한다.

## 📜 TODO

- 실행 가능한 작업 단위로 체크리스트를 작성한다.
- 항목은 5~7개 이내로 유지한다. 더 잘게 쪼개고 싶은 유혹이 들면, 하나의 이슈가 너무 큰 작업을 담고 있다는 신호이므로 이슈 자체를 분리하는 것을 우선 검토한다.
