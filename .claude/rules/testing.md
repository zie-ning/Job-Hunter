# 테스트 규칙

## 원칙

- 테스트 밀도는 기능의 위험도(보안·데이터 무결성 등)에 비례해 정한다. 인증처럼 뚫리면 위험한 기능은 촘촘히, 단순 CRUD는 핵심 경로 위주로 최소한만 작성한다.
- 기능별 테스트 파일(`tests/test_<feature>.py`)만 추가하면 된다. CI의 `pytest` 한 줄이 자동으로 전체를 실행하므로 기능마다 CI 설정을 고칠 필요 없다.
- 커버리지 리포트(pytest-cov)는 도입하지 않는다. 커버리지 %는 "실행 여부"만 보여줄 뿐 "위험도에 맞게 잘 검증되었는지"는 보여주지 않아 이 원칙과 충돌한다. 코드베이스가 커져 "전혀 테스트 없는 파일"을 사람이 추적하기 어려워지면 그때 재검토한다.

## 패턴

- DB: SQLite 인메모리 + `dependency_overrides`
- 외부 API: `respx`로 모킹
- 실제 외부 연동(카카오 등)은 CI가 아니라 수동 E2E로 검증
