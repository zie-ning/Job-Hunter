# PR 작성 규칙

이 문서는 클로드 코드가 이 저장소에서 PR을 작성할 때 참고하는 규칙이다. 템플릿은 [.github/pull_request_template.md](../../.github/pull_request_template.md)를 따른다.

```
## 🛰️ Issue Number

## 🪐 작업 내용

## 📚 추가 리팩토링 가능성
```

## 🛰️ Issue Number

- `closes #<이슈 번호>` 형식으로 작성해 PR이 머지되면 연결된 이슈가 자동으로 닫히도록 한다.
- 관련 이슈가 여러 개면 각각 `closes #<번호>`를 줄바꿈으로 나열한다.

## 🪐 작업 내용

- 과정이 아니라 **이 PR로 무엇을 할 수 있게 됐는지(결과)** 를 기준으로 작성한다. "~을 구현함", "~을 리팩토링함" 같은 작업 나열이 아니라 "~할 수 있다", "~이 추가됐다" 같은 완료된 기능/능력 관점으로 서술한다.
- 여러 기능이 섞여 있으면 가독성을 위해 `###` 하위 섹션으로 기능 단위로 나눈다. 하위 섹션 제목은 그 기능을 한 줄로 요약한다.
- 각 하위 섹션 내용이 한두 문장을 넘어가면 개조식 `-` bullet으로 쪼갠다.

예시:

```markdown
## 🪐 작업 내용

### 이력서 버전 관리
- PDF/문서를 업로드하면 텍스트로 파싱해 에디터에서 구조화된 형태로 편집할 수 있다
- 저장할 때마다 기존 버전은 유지된 채 새 버전이 생성되며, 선택적으로 코멘트를 남길 수 있다

### JD 매칭 점수 계산
- 이력서 버전과 구조화된 JD 간 pgvector 코사인 유사도로 매칭 점수를 자동 계산한다
```

## 📚 추가 리팩토링 가능성

- 작업 중 발견했지만 이번 PR 범위를 벗어나는 개선점(테스트/CI, 코드 품질 자동화, 아키텍처, 성능, 트러블슈팅, 기술적 의사결정 등)을 정리한다. 이는 [.claude/CLAUDE.md](../CLAUDE.md)의 "개선점 발견 시 처리 방식" 지침과 연결된다.
